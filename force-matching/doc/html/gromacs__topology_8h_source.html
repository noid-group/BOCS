125/*
126the flag is the thing you put on the command line to specify that argument.
127 e.g. '-f' for a file
128
129the shift is what I use to keep track of whether or not a flag has been specified
130they work with the 3 unsigned shorts in the tW_gmx_cgmap_input struct
131each struct has its own identifier, most conveniently represented in BINARY
132they're all gonna be something like (1 << n) where n is 0-4 (for files, since there are 5 files)
133which correspond to (in BINARY) 00000001 00000010 00000100 00001000 00010000
134when they pass in, e.g. '-f',
135i first check to see if that flag has already been seen:
136(use_files & files[idx].file_shift) will evaluate to 0 if i have not seen that flag yet
137& is the bitwise AND. it takes two BINARY numbers and compares each digit.
138if a given digit in both numbers is 1, then the result has a 1 in that digit
139if a given digit is 0 in either number, then the result has a 0 in that digit
140once i have verified this is the first time I see that flag, i do
141use_files |= files[idx].file_shift
142|= is the bitwise OR. it takes two BINARY numbers and compares each digit.
143if a given digit in either number is 1, then the result has a 1 in that digit
144if a given digit is 0 in both numbers, then the result has a 0 in that digit
145I find this method of keeping track of what flags we've seen more elegant than
146simply declaring a boolean variable for each flag.
147
148i dont think I actually use the idx... I should get rid of it
149
150and then last is the corresponding parameter that follows the flag
151*/
